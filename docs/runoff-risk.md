# 降雨由来のゴミ濁り・サーフ操作性 初期ルール（2026-11-26）

## 目的と制限

枝葉などがルアーに付着して釣りが成立しづらい状況を、出発前に疑う材料として示す。濁度・ゴミ量・流量の実測、発生確率、回復時刻の予測ではない。魚が釣れないとは断定しない。全魚種への濁り減点、安全度への降雨履歴減点は行わない。落葉の季節補正や沿岸流は未実装。

## データ

- `rainHistory.ts`: Open-Meteo `/v1/jma`。`past_days` と `forecast_days` を対象日から逆算し、対象日の10日前から対象日までを含む期間を複数座標で一括取得。返却後は必要な期間だけ保存する。降水量、風速・風向。`timeformat=unixtime`、JST、m/s。
- `marineWave.ts`: 既存呼出しを対象日の7日前まで拡張。過去波高・周期を再利用。河川は波浪を要求しない。
- 両者は15秒で打切り。雨は30分キャッシュ、最大16件、同時の同一地点・日付の要求を合流。時間選択だけなら再取得しない。
- 代表点は流域の雨の代理であり流域平均ではない。要求座標と返却格子を分ける。同じ格子を足し算しない。用宗・焼津の港内への流入経路は未検証で、弱めの暫定係数を使用。
- 静岡・清水・有東木・鍵穴・高根山は気象庁観測所座標。麻機・丸子は県の河川カメラ位置の周辺モデル値。カメラから雨量を測っていない。
- 古い日付や未来の日付でAPI範囲外・欠損なら不明。別の日付で代用しない。

## 計算

選択した日時をJSTの時単位へ揃える。時間雨量は直前1時間の量で、`target-Nh < time <= target`を集計。24/48/72/168時間すべて欠損を0扱いしない。必須代表点の168時間に欠損があればリスクは不明、追加減点なし。

各時間雨量に `2^(-経過時間/半減時間)` を掛けた残留影響量を使う。流域の保持猶予を引いた経過時間は0未満にしない。これは到達時刻を計算する水文モデルではない。7日窓末尾の24時間は影響を0へフェードさせる。

半減時間はゴミ48〜60時間、濁り30〜36時間。地点別の保持猶予・係数は `runoffProfiles.ts`。いずれも仮説値で、実測から推定した定数ではない。

有効雨は0.5mm/h以上。6時間以内の有効雨を同一の雨イベントとし、最新イベントの前の乾燥期間が72時間以上確認できればゴミ影響を1.25倍。72時間最大雨量が10mm/h以上なら1.15倍。欠損・取得範囲の端までの乾燥は下限値と表示し、欠けた時間を乾燥と数えない。

代表点ごとの影響を地点係数で補正し最大値を採る。5/10/20/40の仮閾値で低め/やや低め/注意/警戒/強く警戒へ分類する。この値は実雨量や確率ではないのでUIにスコアとして出さない。

大浜では降雨の懸念と過去24時間の波高1m以上が重なる場合、再浮遊の注意レベルを1段上げる。向岸風は雨由来の懸念がある場合の補助説明のみ。波・風による追加のゴミ減点はしない。雨由来レベルだけを0/0/8/16/24点の操作性減点へ使用。古いキャッシュは参考表示だけで減点に使わない。

## サーフの波

安全度の波高・周期閾値は維持。操作性は沖の有義波高0.35/0.8/1.0/1.1/1.2/1.5/2/3mで0/22/40/52/58/70/85/100点の暫定負担へ線形補間し、既存の周期負担を加える。港内・河川は変更しない。

浜川河口の2026-11-25 14:30〜17:30、モデル波高1.1〜1.3m台・周期約6秒に対して「竿を立ててもラインを取られる」という1例を初期校正に使用。岸際の波高計算式や安全の境界ではない。低い波・高い波・別の周期で現地検証が必要。

## 表示・チャット

Weatherは選択中の地点・日付・時間に連動したカード。PCでは本文レイアウトに影響しないモーダルダイアログ、スマホでは折り畳み表示。低リスクでも透明やゴミなしを保証しない。詳細に累積雨量、最終有効雨、乾燥時間、取得格子、取得時点で予報だった時間数、暫定係数の制約を表示。

Chatは釣行判断・濁りリスク等の質問で共通の `assessRunoff` と `buildFishingForecast` を使用。指定地点またはWeatherの選択地点を使う。対象日時を明記し、気象・雨・波の一部取得失敗で他情報を捨てない。
